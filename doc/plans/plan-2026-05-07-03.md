# Plan 03 - Port Workflow Review Fixes Back to Template

## Goal

Port the downstream workflow-review fixes back into `template-rust` and
make review comments labeled optional, follow-on, suppressed, or
low-confidence part of the shared gardener heuristic.

## Dependency Graph

```text
T1 workflow guards
  -> T2 review artifacts
      -> T3 review ingestion
T1 -> T4 validation scripts
T1 -> T5 audit and tests
T2, T3 -> T6 gardener docs
```

## Tasks

### T1 - Refresh workflow safety guards

- Problem or motivation: the downstream PRs found small guardrail gaps
  around cleanup traps, merge preconditions, and repo-resolution prose.
- Solution / implementation approach: harden `scripts/pr_request.sh`
  cleanup, make `scripts/git_merge.sh` refuse dirty worktrees before
  merge checks, and clarify `scripts/github_client.py`'s target-repo
  docstring.
- Types or API surface: workflow script behavior only; no Rust API
  changes.

### T2 - Fix review-state and review-artifact handling

- Problem or motivation: review files are part of the FSM state, but
  local review detection still misses branch-local review docs and the
  Codex local-review path appends without committing.
- Solution / implementation approach: infer a single branch-local
  `doc/reviews/review-*.md` from `git diff origin/main...HEAD`, commit
  local-review output in `scripts/pr_review.sh`, and update `/pr-review`
  docs so review artifacts ride with code fixes or doc-only review
  commits.
- Types or API surface: `scripts/workflow_state.sh` gains local review
  doc inference; `scripts/pr_review.sh` becomes an append-and-commit
  transition.

### T3 - Fix GitHub review ingestion and `/pr-watch`

- Problem or motivation: malformed GitHub API responses should fail
  clearly, and ask-only review rounds should not discard mirrored
  review-doc history.
- Solution / implementation approach: make `scripts/pr_report.py`
  reject non-list JSON from list endpoints, keep mirrored review docs in
  `/pr-watch` ask-only rounds, and key push-failure recovery state to
  the failed `HEAD`.
- Types or API surface: no new CLI flags; existing review commands get
  stricter failure behavior and better state recovery.

### T4 - Port validation-script hardening

- Problem or motivation: the layer parser can stop multiline grouped
  imports too early, and the PII scanner needs a committed-tree mode for
  history or CI checks.
- Solution / implementation approach: collect grouped imports until the
  terminating semicolon, add `scripts/check_pii.sh --tree <ref>`, and
  update docs/help text for both behaviors.
- Types or API surface: `scripts/check_pii.sh --tree <ref>` is a new
  documented CLI mode.

### T5 - Port audit and test fixes

- Problem or motivation: forced audit runs should not probe
  since-last state, and the workflow-state test still wraps env vars
  that the helper clears.
- Solution / implementation approach: make `scripts/audit_run.py run
  --force` go directly to tracked files, assert that behavior in
  `tests/test_audit_run.py`, and remove the ineffective
  `mock.patch.dict` in `tests/test_workflow_state.py`.
- Types or API surface: audit CLI behavior is unchanged in intent but
  avoids an unnecessary and potentially failing probe.

### T6 - Codify stronger gardener review handling

- Problem or motivation: agents can underweight comments presented as
  optional, follow-on, suppressed, or low-confidence even when the
  finding is valid and small.
- Solution / implementation approach: extend
  [Be a Good Gardener](../../AGENTS.md#be-a-good-gardener) so these
  comments are treated with the same seriousness as ordinary review
  comments unless they are large, complex, outside sprint scope, or
  incorrect. Link review command docs and workflow prose back to that
  section.
- Types or API surface: documentation and command-playbook behavior
  only.
